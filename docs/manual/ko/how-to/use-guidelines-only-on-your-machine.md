# 내 머신에서만 지침 쓰기

이 문서는 커밋되는 파일을 바꾸지 않고, 나에게만 프로젝트 선택에 블록을 더하거나 거기서 빼는 방법을 안내합니다.
팀과 쓰는 도구가 다른 작업자, 그리고 그 일을 대신 하는 에이전트를 위한 문서입니다.

`guideline.json` 의 프로젝트 선택은 팀의 것으로 그대로 둡니다.
내 더함과 뺌은 **개인 선택**이며, git 자신의 폴더에 저장되고 커밋되지 않습니다.

## 시작하기 전에

- 프로젝트가 이미 지침을 받았어야 합니다(`guideline.json` 이 있음). 아니면 먼저 `guideline pick` 을 실행하세요.
- 프로젝트가 git 저장소 안에 있고 git 이 2.31 이상이어야 합니다. git 이 없으면 `pick --local` 은 종료 코드 2 로 멈춥니다.
- 지침 서버가 0.24 이상이어야 합니다. 옛 서버는 개인 폼을 몰라 `pick --local` 이 「이 서버는 개인 폼을 모름」 으로 멈춥니다(종료 코드 1).

## 내 블록 고르기

1. 단위 디렉터리에서 `pick --local` 을 실행합니다.

   ```bash
   guideline pick --local
   ```

   폼이 부제 「내 개인 선택」 으로 열립니다. 원본은 프로젝트가 받은 리비전으로 보입니다.

2. 블록마다 **그대로**·**더함**·**뺌** 중 하나를 고릅니다.
   - 행마다 프로젝트가 그 블록을 받는지 보입니다. 프로젝트가 받는 블록은 더함이, 받지 않는 블록은 뺌이 꺼져 있습니다.
   - 하위 스택을 더하면 조상도 더합니다. 스택을 빼면 그 아래 스택도 뺍니다.
   - **필수** 블록은 「필수 — 뺄 수 없음」, 그것을 품은 스택은 「필수 블록을 품음 — 뺄 수 없음」 으로 보입니다.
3. **확인**에서 더할 것과 뺄 것을 봅니다. 다른 프로젝트에서도 이 선택으로 폼을 미리 체크하려면 **이 선택을 내 기본값으로** 를 체크합니다([머신 기본값](#머신-기본값) 참고).
4. **제출하고 내 선택 저장**을 누릅니다.

터미널은 `pick` 처럼 쓴 생성물을 보입니다.

```text
반영 완료(r3) — 쓴 파일 2, 지운 파일 0
  쓰기  .ruler/extra/00-e.md
  쓰기  .ruler/guideline.md
```

`git status` 에는 바뀐 것이 없습니다: 커밋되는 것은 아무것도 쓰지 않았습니다.

에이전트에게 고르게 하려면 [에이전트에게 추천받기](#에이전트에게-추천받기)를 보세요.

## 바뀌는 것과 그대로인 것

| 무엇 | 자리 | 커밋 |
| --- | --- | --- |
| 내 개인 선택 | `<git 공용 디렉터리>/guideline/units/<단위 키>/local.json` | 안 함 |
| 내가 더한 블록의 사본 | `<git 공용 디렉터리>/guideline/units/<단위 키>/.guideline/` 과 `guideline-lock.json` | 안 함 |
| 내 선택에서만 나온 생성물과 ruler 의 에이전트 설정 파일 | `<git 공용 디렉터리>/info/exclude` 의 이 단위·워크트리 블록에 적힘 | 안 함 |
| 이 워크트리가 쓰는 역할([워크트리마다 역할 쓰기](#워크트리마다-역할-쓰기)) | `<git 디렉터리>/guideline/role` | 안 함 |
| `guideline.json`, `guideline-lock.json`, `.guideline/`, `.gitignore` 블록 | 바뀌지 않음 | 지금처럼 커밋 |

`<git 공용 디렉터리>` 는 보통의 클론에서 `.git/` 입니다.
`<git 디렉터리>` 는 그 워크트리 자신의 git 디렉터리입니다: 메인 워크트리는 `.git/`, 링크 워크트리는 `.git/worktrees/<이름>/` 입니다.
단위 키는 git 루트 단위면 `%root`, 그 밖은 단위 경로를 URL 인코딩한 것입니다. 예: `packages%2Fapi`.

받는 것은 프로젝트 선택에 내 더함과 그 조상 스택을 더하고, 내 뺌과 그 아래 스택을 뺀 것입니다.
관리 지침(`.ruler/guideline.md`)에는 그것을 적은 「이 작업자의 개인 범위」 절이 붙습니다.
`guideline status` 는 두 줄을 더 보입니다.

```text
  개인 범위 — 더함 1: rules/extra
  개인 범위 — 뺌 0: -
```

> [!NOTE]
> `<git 공용 디렉터리>/guideline/` 의 개인 사본은 고치지 마세요. `guideline update` 가 덮어쓰고, `guideline propose` 는 보내지 않습니다. 팀의 지침을 고치려면 `.guideline/` 의 사본을 고쳐 제안하세요.

## 스킬·서브에이전트·MCP 서버

ruler 는 이것들을 에이전트 설정(`.mcp.json`, `.claude/skills/` 등)에 쓰고, 그 파일들을 `.gitignore` 의 자기 블록에 적습니다.
개인 선택이 그중 무엇이 있는지를 바꿔도 커밋되는 `.gitignore` 는 프로젝트 선택대로입니다:

- ruler 를 개인 선택으로 돌리기 전에, CLI 가 임시 폴더에서 프로젝트 선택만으로 ruler 를 한 번 더 돌리고 그 `.gitignore` 를 나중에 되돌려 둡니다. 개인 선택으로만 생기는 설정 파일(예: 프로젝트에 MCP 서버가 없을 때의 `.mcp.json`)은 대신 이 워크트리의 `info/exclude` 블록에 적힙니다.
- ruler 는 더 받지 않는 MCP 서버·스킬·서브에이전트를 지우지 않습니다. 개인으로 뺀 것, 전에 더했다가 이제 더하지 않는 것은 CLI 가 `.mcp.json`, `opencode.json`, `.codex/config.toml`, `.claude/skills/`, `.agents/skills/`, `.opencode/skills/`, `.claude/agents/`, `.codex/agents/` 에서 지웁니다.
- 전에 더한 것 때문에만 생긴 설정 파일·폴더라도 손으로 둔 것이 남아 있으면 그대로 둡니다. 손으로 둔 설정 파일이나 다른 에이전트 설정에 ruler 가 남기는 `.bak` 백업도 그대로 둡니다(손으로 둔 파일의 `.bak` 은 사람 원본이라 그 파일이 지워져도 둡니다). 개인 선택으로만 생겼다가 CLI 가 지운 claude·codex·opencode 설정의 `.bak` 은 함께 지웁니다. 남긴 것은 `ruler-leftover` 할 일이 알립니다.
- CLI 는 이 에이전트들의 설정만 압니다. `.ruler/ruler.project.toml` 로 켠 그 밖의 에이전트(예: Cursor)의 설정은 건드리지 않고 `ruler-leftover` 할 일로 알립니다: 그 에이전트 설정에서 서버를 직접 지우세요.

개인 선택은 `pick --local` 로 비우세요. `local.json` 을 지우거나 손으로 비우면 프로젝트 MCP 위에 더했던 서버는 남으니 `.mcp.json` 등에서 직접 지워야 합니다.

개인 선택이 없거나 비어 있으면 전과 같습니다: ruler 혼자 정하고, 프로젝트가 뺀 서버·스킬은 남겨 둡니다.

> [!WARNING]
> 나나 프로젝트가 스킬을 하나라도 고르면 ruler 는 돌 때마다 스킬 폴더(`.claude/skills/` 등)를 통째로 바꿉니다. 손으로 둔 스킬 폴더는 할 일 없이 사라집니다. 내 스킬은 다른 곳에 두세요.

## 워크트리와 클론

- **한 클론의 모든 워크트리가 개인 선택을 함께 씁니다.** git 공용 디렉터리를 함께 쓰기 때문입니다. 새 워크트리에서는 `guideline apply` 가 서버 없이 그것을 조합합니다.
- `info/exclude` 의 블록은 워크트리마다 따로입니다(`# START guideline personal files <단위 경로> @<워크트리>`, `.` 은 git 루트 단위와 메인 워크트리). 그래서 프로젝트 선택이 다른 브랜치끼리 서로의 생성물을 가리지 않습니다. 지운 워크트리의 블록은 다음에 쓸 때 사라집니다.
- 개인 사본은 이 브랜치의 프로젝트가 이미 고른 블록이라도 더한 것을 모두 담습니다: 다른 브랜치의 워크트리는 그 블록을 고르지 않았을 수 있습니다. 프로젝트가 고른 곳에서는 프로젝트 사본을 씁니다. 사본은 `pick --local` 에서 그 더함을 뺄 때만 지웁니다.
- 더한 블록에 개인 사본이 없으면(받은 적이 없거나 지워졌으면) 조합하지 않고 `scope: "personal"` 인 `no-copy` 할 일을 냅니다. `guideline update` 로 받으세요.
- 다른 클론이나 다른 머신에는 거기서 `pick --local` 을 실행하기 전까지 개인 선택이 없습니다.
- 역할은 워크트리마다 따로 씁니다. 다음 절을 보세요.

## 워크트리마다 역할 쓰기

**개인 역할**은 공통 개인 선택 위에 얹는, 이름 붙은 더함·뺌 묶음입니다.
워크트리마다 역할 하나를 쓸 수 있습니다.
예를 들어 한 클론의 워크트리 하나는 프런트엔드 스택을, 다른 하나는 백엔드 스택을 받습니다. 두 워크트리 모두 커밋되는 파일과 `git status` 는 그대로입니다.

역할이 있는 워크트리는 세 겹을 조합합니다.

1. `guideline.json` 의 프로젝트 선택.
2. `guideline pick --local` 로 고른 공통 개인 선택. 모든 워크트리가 함께 씁니다.
3. 2번 결과 위에 얹는 역할의 더함·뺌.

역할이 없는 워크트리는 전과 똑같이 조합합니다.
환경 변수로는 역할을 바꾸지 않습니다.

### 역할 정의하기

1. 단위 디렉터리에서 역할 이름을 붙여 `pick --local --role` 을 실행합니다.

   ```bash
   guideline pick --local --role frontend
   ```

   역할 이름은 영소문자로 시작하고 영소문자·숫자·`-` 로 32자 이내입니다. 다른 이름이나 `--local` 없는 `--role` 은 폼을 열기 전에 종료 코드 2 로 멈춥니다.

2. 출처마다 열리는 개인 폼에서 역할의 블록을 고릅니다. 위에서 설명한 개인 폼과 두 가지가 다릅니다.
   - 받는지 보이는 열이 「프로젝트·공통 선택이 받음」 입니다. 역할은 프로젝트 선택에 공통 개인 선택을 입힌 결과 위에 얹힙니다.
   - 부제가 「개인 선택 — 역할 frontend」 로 끝납니다. 0.24 서버는 역할을 무시해 보통의 개인 폼과 「프로젝트가 받음」 을 보이지만, 결과는 같습니다.
3. 제출합니다. 역할이 없으면 새로 만듭니다.

폼은 그 역할의 지금 정의를 미리 체크합니다. 정의가 없으면 그 서버에 저장한 그 역할의 기본값을, 그것도 없으면 아무것도 체크하지 않습니다.
**이 선택을 내 기본값으로** 는 공통 기본값과 따로, 그 서버의 이 역할 기본값으로 저장합니다.

결과는 이 단위 `local.json` 의 `roles.frontend` 에 들어갑니다. 공통 선택은 바뀌지 않습니다.
`pick --local --role` 은 역할에 필요한 개인 사본을 받지만, 이 워크트리를 그 역할로 바꾸지는 않습니다. 이 워크트리가 이미 쓰는 역할로 조합합니다.

역할은 공통 선택의 결과 위에 얹히므로, 나중에 공통 선택을 바꾸면 역할도 따라갑니다.
공통 선택이 그 아래 블록을 더해서만 받는 스택은, 역할이 그 아래 블록만 빼면 남습니다.
그 스택도 빼려면 역할 폼에서 부모 스택을 빼세요.

### 이 워크트리를 역할로 바꾸기

```bash
guideline role use frontend
```

- 역할 이름을 `<git 디렉터리>/guideline/role` 에 씁니다. 다른 워크트리의 역할은 그대로입니다.
- 그다음 어느 단위에서 실행하든 git 루트에서 `guideline apply` 처럼 반영합니다. 지난 역할만 더했던 MCP 서버와 스킬은 에이전트 설정에서 지웁니다.
- 그 역할이 워크트리의 단위 하나 이상에 정의돼 있어야 합니다. 아니면 「역할 frontend 이(가) 어느 단위에도 정의돼 있지 않음」 으로 종료 코드 2 입니다.
- 아무것도 쓰기 전에 반영이 실패하면 역할을 되돌리고, 메시지가 되돌린 역할을 알립니다.
- 파일을 쓴 뒤 반영 일부가 실패하면(예: git 루트 아래 단위) 역할은 그대로 새 역할입니다. 메시지가 말하는 원인을 고친 뒤 `guideline apply` 를 실행하세요.

다른 명령:

| 명령 | 하는 일 |
| --- | --- |
| `guideline role` | 이 워크트리의 역할과 단위마다 정의된 역할을 보입니다 |
| `guideline role use --none` | 역할을 지우고 같은 방식으로 반영합니다 |
| `guideline role remove <이름>` | 이 단위 `local.json` 에서 그 역할의 정의를 지웁니다. 반영하지 않습니다. 이 워크트리의 역할이면 `apply` 할 일을 냅니다 |

`guideline status` 는 개인 범위 줄 옆에 역할 겹을 보입니다.

```text
  역할 — frontend
  개인 범위 — 더함 1: rules/extra
  개인 범위 — 뺌 0: -
  역할 frontend — 더함 1: rules/web
  역할 frontend — 뺌 0: -
```

관리 지침의 개인 절에는 역할과 그 역할이 더하고 뺀 것이 보입니다.

### 역할과 단위

역할 정의는 단위마다 그 단위의 `local.json` 에 있지만, 워크트리의 역할은 하나입니다.

- 워크트리의 역할을 정의하지 않은 단위는 공통 선택만으로 조합합니다. 그 단위의 `status` 는 「역할 frontend — 이 단위에는 정의돼 있지 않아 공통 개인 선택만 씀」 을 보입니다.
- 어느 단위도 그 역할을 정의하지 않으면 `role-missing` 할 일을 내고 공통 선택만 씁니다. `guideline pick --local --role <이름>` 으로 정의하거나 `guideline role use --none` 을 실행하세요.
- 역할 파일에 올바른 역할 이름이 없으면 `role-bad` 할 일을 내고 역할 없이 조합합니다. `guideline role use <이름>` 이나 `guideline role use --none` 을 실행하세요.
- `guideline update` 는 어느 워크트리에서 실행하든 모든 역할의 더함에 필요한 개인 사본을 받습니다. 나중에 역할을 바꾸는 워크트리에도 사본이 준비돼 있습니다.

## 최신으로 유지하기

`pick --local` 은 내 사본을 프로젝트 잠금의 리비전으로 받습니다.
`guideline update` 가 프로젝트와 내 사본을 함께 최신 리비전으로 올립니다.

다른 워크트리에서 `update` 하면 내 사본이 이 워크트리의 프로젝트 사본보다 새 리비전일 수 있습니다.
그러면 `apply` 와 `status` 가 `personal-revision` 할 일을 냅니다. 여기서 `guideline update` 를 실행해 맞추세요.

## 필수 블록

프로젝트는 누구도 뺄 수 없는 블록을 정할 수 있습니다.
프로젝트의 고르기 폼(`guideline pick`)에서 고른 블록에 **필수** 칸이 있습니다.
그 목록은 `guideline.json` 의 `sources.<이름>.required` 에 적히고, 커밋합니다.

- 필수 블록과 그 위의 모든 스택은 개인 선택에서 뺄 수 없습니다.
- 내가 뺀 뒤에 블록이 필수가 되면 내 뺌은 무시되고 `personal-ignored` 할 일이 나옵니다. `guideline pick --local` 로 정리하세요.
- 에이전트도 그 뺌을 추천할 수 없습니다: `pick --local --recommend` 가 종료 코드 2 로 멈춥니다.

## 머신 기본값

**이 선택을 내 기본값으로** 는 내 더함과 뺌을 서버 주소마다 `~/.config/guideline/defaults.json`(`XDG_CONFIG_HOME` 이 있으면 `$XDG_CONFIG_HOME/guideline/`)에 저장합니다.

- 그 출처에 개인 선택이 아직 없는 프로젝트에서 개인 폼을 미리 체크하는 데만 씁니다. 폼에 「미리 체크: 내 기본값」 이 보입니다.
- 원본에 없는 블록은 미리 체크하지 않습니다.
- `update`·`apply` 는 읽지 않으므로, 기본값을 바꿔도 어느 프로젝트도 바뀌지 않습니다.
- 마지막으로 기본값을 저장한 실행이 그 서버의 기본값을 정합니다. 한 실행이 같은 서버의 출처 여럿을 저장하면 선택을 합칩니다. 어떤 블록을 출처마다 다르게 골랐으면 이름 순으로 뒤 출처의 것을 남기고 CLI 가 경고합니다.

## 더한 스택 세팅하기

세팅 문서가 있는 스택을 더하면 `setup` 대신 `setup-personal` 할 일이 나옵니다.
관리 지침의 세팅 표에는 「개인」 으로 표시됩니다.

`docs/guideline/<스택>/SETUP.md` 를 따르되 **커밋되는 파일은 바꾸지 마세요.** 예: `package.json`, 커밋되는 설정 파일, `.gitignore`, `.ruler/ruler.project.toml`.
개인 선택은 프로젝트를 그대로 두어야 합니다.
내 머신이나 추적되지 않는 파일에서 끝나는 단계는 합니다. 커밋되는 파일을 바꿔야 하는 단계는 팀과 정하세요.

`guideline-sync` 스킬도 에이전트에게 같은 방식을 시킵니다.

## 에이전트에게 추천받기

`guideline-sync` 스킬이 있는 에이전트가 대신 고를 수 있습니다.
에이전트는 스택마다 `when` 을 읽습니다. 「<도구>를 쓰는 작업」 스택은 내가 그 도구를 쓸 때 맞습니다.
에이전트는 이런 파일을 쓰고 `guideline pick --local --recommend <파일>` 을 실행합니다.

```json
{ "add": { "rules/browser/browseros-neo": "you use BrowserOS neo" }, "remove": { "rules/orca": "you do not use Orca" } }
```

폼은 그 선택이 체크되고 표시된 채로 열립니다.
그냥 `{ "블록 키": "이유" }` 는 더함입니다.
원본에 없는 키나 필수 블록의 뺌은 폼을 열기 전에 종료 코드 2 로 멈춥니다.

## 한계

- **git 에서만.** git 저장소 밖의 단위에는 개인 범위가 없습니다.
- **프로젝트의 출처만.** `guideline.json` 에 있는 출처의 블록만 더할 수 있습니다.
- **다른 출처의 같은 이름.** 프로젝트가 다른 출처에서 같은 최종 이름의 블록을 골랐으면 내 더함은 쓰이지 않습니다. `pick --local` 은 그것과 그 아래 블록을 저장하지 않고 `personal-shadowed` 할 일을 냅니다. 더한 뒤에 프로젝트가 그 블록을 고르면 내 더함과 그 아래에 더한 블록도 쓰지 않아, 다른 출처의 스택에 섞이지 않습니다.
- **모노레포 하위 디렉터리.** 스킬·서브에이전트·MCP 서버는 git 루트에서만 받지만, 하위 디렉터리의 개인 폼은 그것들을 더하는 것을 막지 않습니다. git 루트의 개인 선택에서 더하세요.
- **옛 CLI.** 이 CLI 는 `local.json` 과 `defaults.json` 을 버전 2 로 씁니다. 0.24.0 CLI 는 그것을 읽지 못합니다: 그 `apply`·`update`·`status` 는 프로젝트 선택만으로 조합하고(`local-bad` 할 일), 그 `pick --local` 은 종료 코드 1 로 멈춥니다. 클론을 쓰는 모든 곳의 CLI 를 올리세요.
- **깨진 파일.** `local.json` 을 읽을 수 없으면 `apply` 는 프로젝트 선택만으로 조합하고(`local-bad` 할 일), `pick --local` 은 그 파일을 덮어쓰지 않고 종료 코드 1 로 멈춥니다. 파일을 고친 뒤 `guideline apply` 로 개인 선택을 되살리고, 바꾸려면 그다음 `pick --local` 로 다시 고르세요. 파일을 지우면 프로젝트 MCP 위에 더했던 서버는 남으니 `.mcp.json` 등에서 직접 지워야 합니다.
